# GUIDE-20260905 — Instruções e distribuição

## Objetivo e limites

Reduzir contexto obrigatório e bloqueios artificiais, preservando a semântica ESAA.
Escopo aprovado: AGENTS, README, templates de workspace, guias PT/EN de runners e CLI,
cinco perfis PARCER, descrições do contrato empacotado e testes de distribuição.
Não alterar gates, schemas, defaults, permissões ou transições; não publicar pacotes.
As mudanças locais preexistentes em plugins.py, test_plugin_manager.py e
create-workflow-esaa-core.md ficam fora desta entrega.

## Arquitetura e compatibilidade

AGENTS raiz aponta para contratos locais e guias do repositório. O AGENTS distribuído
é portátil e referencia contratos efetivamente instalados; .claude/CLAUDE.md aponta
para ../AGENTS.md. O README instalado é introdutório e não aponta para docs ausentes.
Guias PT/EN recebem alterações equivalentes, com blocos de código idênticos.
Os perfis mantêm metadados de identidade e chaves superiores; seu conteúdo é
orientação especializada, não outra implementação do runtime.

Os contratos ativos em .roadmap são protegidos por forbidden_write, que prevalece
sobre boundary_grant. Esta entrega revisa os templates publicados sem atualizar
os arquivos ativos. Os testes distinguem divergência editorial de semântica
executável; os perfis ativos antigos não serão copiados sobre os novos.
A futura atualização de consumidores continua explícita pelos modos de bootstrap.

## Critérios de aceitação

1. Entradas curtas, referências resolvíveis, sem leitura ampla obrigatória.
2. Contexto recuperável não causa interrupção; requisitos materiais, boundaries,
   lessons obrigatórias e falhas de integridade permanecem restrições.
3. complete somente após critérios e verificações reais, sem equivaler a review
   ou publicação. JSON puro somente na submissão.
4. Contrato empacotado difere apenas em description; schemas/gates/políticas intactos.
5. Cinco perfis YAML válidos, com identidades e chaves superiores preservadas.
6. Bootstrap padrão/public/production, preserve/merge/force preservam seus contratos;
   referências existem no wheel instalado fora do checkout.
7. Testes focados, suíte completa, wheel/sdist, smoke instalado e verify documentados.

## Cenários de avaliação

| Cenário | Resultado esperado |
| --- | --- |
| Consulta | Leitura proporcional; nenhuma transição |
| Correção pequena | Contexto relacionado, preparação local e efeito pelo Orchestrator |
| Implementação e validação | Executar, inspecionar e corrigir até critérios satisfeitos |
| Contexto recuperável | Buscar a fonte disponível dentro dos limites |
| Requisito materialmente ambíguo | Obter decisão antes da ação dependente |
| Boundary insuficiente | Não aplicar efeito; reportar impedimento |
| Tarefa done | Não reabrir; issue e hotfix conforme protocolo |
| Warning | Considerar; não converter em bloqueio sem exigência concreta |
| Lesson obrigatória | Respeitar reject/require_field/require_step |
| Lock ativo/transitório | Runtime gerencia contenção; nunca remover manualmente |
| Timeout/corrupção/read-after-write inválido | Parar operação afetada e relatar evidências |
